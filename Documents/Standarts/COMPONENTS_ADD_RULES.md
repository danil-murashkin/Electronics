# Правила добавления компонента (Components Add Rules)

Порядок добавления новой серии — §0. Его читают целиком и идут по шагам.
§1–16 — обрисовка чипа с двумя пятаками. §17 — выгрузка STEP. База Altium — шаг 5 в §0.
Числа корпуса и land pattern берутся из PDF в `Datasheets`, не из памяти и не из другой серии.

**Эталонная реализация:** `Discrete_Resistors_Ceramic_SMD.PcbLib` (префикс `RESC*`).  
Числовой снимок: `overlay_params.json`.  
Скрипты: `redraw_all_m1.py`, `redraw_top_overlay.py`, `redraw_top_border.py`,
`redraw_designator_comment.py`, `clone_nm_variants.py`, `strip_nm_variants.py`,
`restore_nm_m9_frame.py`.

---

## 0. Новая серия

Так добавляют серию, которой ещё нет: диоды, индуктивности и любой другой корпус, не только резисторы и конденсаторы. Шаги 1 и 2 делает человек. Шаги 3–5 делает агент после того, как эти файлы уже лежат в каталоге серии.

Каталог серии повторяет резисторы и конденсаторы:

```
Datasheets\     PDF серии и PDF Footprint / Mount
Packages\       Name.ipt, Name.py, Name.xlsx, Name_<размер>.step
Footprints\     Name.PcbLib
Database\       Name_GOST.xlsx и Name_GOST.DbLib
Symbols\        Name.SchLib
```

Имя `Name` одно на серию, как `Discrete_Resistors_Ceramic_SMD` и `Discrete_Capacitors_Ceramic_SMD`.

### Шаг 1. Документация — делает человек

В `Datasheets` кладёт два PDF:

- документацию серии (электрические параметры, коды корпуса, допуски);
- документ Footprint / Mount (размеры корпуса и рекомендуемая посадка).

Имена файлов содержат серию, как `Discrete_Resistors_Ceramic_SMD_Yageo_RC_L_Series.pdf` и `Discrete_Resistors_Ceramic_SMD_Yageo_Mount.pdf`. Агент не скачивает документы сам и не подставляет размеры из другой серии.

### Шаг 2. Параметрическая деталь — делает человек

В `Packages` появляется один `.ipt` на всю серию корпусов. Размеры, которые меняются от типоразмера к типоразмеру, — пользовательские параметры Inventor (`vL`, `vW`, `vH`, длины поясков и остальные, которые есть в модели). Надпись на корпусе, если она нужна, завязана на текстовый параметр `vTextSize`. Агент модель не строит и чужой `.ipt` не пересохраняет.

### Шаг 3. STEP — делает агент

Агент читает PDF из шага 1 и заполняет `Name.xlsx` номиналами до знака ±. Затем копирует скрипт соседней серии (`Capacitors_SMD.py` или `Discrete_Resistors_Ceramic_SMD.py`), называет его `Name.py` и кладёт рядом с `.ipt`. Скрипт по-прежнему находит деталь и таблицу по своему имени (§17). Колонки таблицы — параметры этого `.ipt`, не фиксированный список резистора.

Запуск: `py -3 Name.py`. Проверка: тело совпало с `vL × vW × vH`, надпись не шире промежутка между контактами.

### Шаг 4. Посадочные места — делает агент

По Mount-PDF и уже собранным STEP агент делает `Footprints\Name.PcbLib`. Для чипа с двумя пятаками геометрия считается по §1–14, модель вкладывается по §15, файл записывается только когда библиотека в Altium закрыта (§16). Для другого корпуса (SOD, SMA, SOT) число пятаков и контур берутся из Mount-PDF; формулы двух пятаков туда не переносятся, пока для этого корпуса нет своего раздела.

Эталон сборки двух пятаков с вложенным STEP: `Discrete\Capacitors\Ceramic\Footprints\build_capacitor_footprints.py`.

### Шаг 5. База компонентов — делает агент

В `Database` появляются два файла с одним именем: `Name_GOST.xlsx` и `Name_GOST.DbLib`.

Книга Excel, лист `List`. Обязательные столбцы связи с Altium, как у `Discrete_Diodes_Schottky_SMD_GOST.xlsx` и `Discrete_Resistors_Ceramic_General_SMD_GOST.xlsx`:

| Столбец | Содержание |
|---|---|
| `Item ID` | ключ строки, по нему DbLib выбирает запись |
| `Description` | текст компонента |
| `Library Ref` | имя символа в `.SchLib` |
| `Library Path` | путь к `Symbols\Name.SchLib` |
| `Footprint Ref` | имя footprint в `.PcbLib` |
| `Footprint Path` | путь к `Footprints\Name.PcbLib` |

Остальные столбцы — параметры серии из PDF шага 1 (номинал, корпус, допуски, производитель, поставщик, URL даташита). `Length`, `Width`, `Height` — те же номиналы, что в STEP. Несколько плотностей посадки — дополнительные пары `Footprint Ref N` / `Footprint Path N`, как у резисторов.

`.DbLib` смотрит на книгу рядом с собой, не на чужой абсолютный путь:

```
LibraryDatabaseType=Microsoft Excel 2007
LibraryDatabasePath=Name_GOST.xlsx
DatabasePathRelative=1
TableName=List$
```

`Item ID` — поле ключа (`FieldType=0`). `Description`, ссылки на символ и footprint — поля параметров (`FieldType=1`). Образец разметки полей — `Discrete_Diodes_Schottky_SMD_GOST.DbLib`. Строка `ConnectionString` в старых файлах может содержать устаревший диск; рабочей ссылкой остаётся `LibraryDatabasePath` при `DatabasePathRelative=1`.

Символа ещё нет — агент заводит `Symbols\Name.SchLib` и пишет его имя в `Library Ref`. Без символа строку базы не заполняют.

Все размеры в **мм**, если не сказано иначе.  
Координаты линий округлять до **0.01 mm** (знакосимметрично).  
Толщины линий хранить точно (в т.ч. `0.025`), без округления до 0.01.

### Словарь краёв линии

Линия имеет толщину `w`. Для прямоугольника с centerline `±ox, ±oy`:

| Понятие | Формула |
|---|---|
| Centerline | середина штриха |
| Внутренний край | ближе к центру корпуса: `ox − w/2` |
| Внешний край | дальше от центра: `ox + w/2` |

Правила Clear / mask всегда задаются через **края**, не через centerline «на глаз».

### Именование footprint

```
{PREFIX}{SIZE}{DENSITY}[_{HH}|_NM]
```

| Часть | Пример | Смысл |
|---|---|---|
| `PREFIX` | `RESC`, `CAPC`, … | семейство |
| `SIZE` | `0805`, `0075` | EIA / метрический код |
| `DENSITY` | `L` / `N` / `M` | IPC-7351 Least / Nominal / Most |
| `_{HH}` | `_08` | код высоты, если у одного EIA несколько корпусов |
| `_NM` | суффикс | Not Mounted / DNP; встаёт **вместо** `_{HH}` |

`L/N/M` — уровни плотности посадки, не коды производителя.

Если у одного EIA несколько высот, код высоты — это суффикс имени STEP (две цифры), а не пересчитанный `body_H`. Номинал может не совпадать с десятыми: файл `1206_08` может хранить высоту 0.85 мм. Один и тот же размер и плотность с разной высотой совпадают по меди, шелкографии, M1 и M9; различаются вложенный STEP и `OVERALLHEIGHT`. `_NM` один на размер и плотность: высоты нет, 3D нет.

## 1. Входные данные (обязательно до отрисовки)

Из datasheet / land-pattern таблицы:

| Символ | Что это |
|---|---|
| `body_L`, `body_W`, `body_H` | габарит корпуса |
| `I1`, `I2` | длины терминалов по длинной оси (если есть) |
| `Xc` | расстояние от центра footprint до центра пятака по X |
| `padX`, `padY` | размеры меди пятака |
| `SME` | Solder Mask Expansion (одинаковый на все стороны пятака) |

Для двух пятаков по умолчанию: центры `(±Xc, 0)`, без Offset X/Y (**Offset = 0**).

Производные:

```
pad_outer_x = Xc + padX / 2
pad_outer_y = padY / 2
pad_inner_x = Xc − padX / 2
mask_outer_x = pad_outer_x + SME
mask_outer_y = pad_outer_y + SME
SPAN        = 2 × pad_outer_x          # полный габарит меди по X
```

## 2. Диапазоны типоразмеров (bands)

Диапазон задаёт **толщины линий** и **Clear**. Границы — по короткой стороне корпуса / EIA-коду; для новой серии сопоставь размер с ближайшим band.

| Band | Типичные коды | Линии | Clear |
|---|---|---|---|
| **1** | 0075, 0100 | тонкие | минимальный |
| **2** | 0201 | средний | промежуточный |
| **3** | 0402 … 1218 | стандарт | стандарт |
| **4** | 2010, 2512 | как band 3 | увеличенный |

Эталонные Clear (silk → mask):

| Band | Clear для N и L | Clear для M |
|---|---|---|
| 1 | 0.025 | 0.05 |
| 2 | 0.05 | 0.08 |
| 3 | 0.10 | 0.15 |
| 4 | 0.15 | 0.25 |

**Clear** — зазор от **внешнего края mask** до **внутреннего края** шелкографии (TO).

---

## 3. Плотности IPC (L / N / M)

| Суффикс | IPC | Пятаки | Top Overlay | Clear |
|---|---|---|---|---|
| **N** | Nominal (B) | номинал datasheet | две линии и дуги по X | базовый band |
| **M** | Most (A) | больше toe/side | две линии и дуги по X | увеличенный band |
| **L** | Least (C) | меньше toe/side | **две дуги**, не рамка | как у N |

При масштабировании L/M от N:

- меняется toe (`pad` вдоль оси выводов) и side (поперёк);
- **`Xc` не сдвигается** — медь растёт/сжимается под терминалами;
- у **L** ширина пятака `padY ≥ body_W`.

Конкретные Δtoe / Δside — из политики серии (для Yageo RC см. §A).

---

## 4. Толщины линий (общее правило)

```
M1_w  = f(band)          # Mechanical 1 / «TopPackage»
TO_w  = 2 × M1_w         # Top Overlay
M9_w  = M1_w             # Top Border (Mechanical 9)
```

Эталон:

| Band | M1_w | TO_w | M9_w |
|---|---|---|---|
| 1 | 0.025 | 0.05 | 0.025 |
| 2 | 0.05 | 0.10 | 0.05 |
| 3 и 4 | 0.10 | 0.20 | 0.10 |

## 5. Пятаки и Solder Mask

1. Два SMD-пятака на Top Layer.
2. Paste — по правилам библиотеки / Altium (обычно как у меди для чипа).
3. Mask: expansion = `SME` (Manual на мелких, Rule допустим на крупных).
4. Pad Offset X/Y = **0**.
5. Пятак в Pad Stack — **Rounded Rectangle**, не Custom Shape. Эталон — `CAPC0080L_01` (у `CAPC0080L_NM` стека нет, поэтому там остаётся Custom Shape). Запись — поток `CustomShapes`: `S0.SHAPEKIND=3`, `S0.XSIZE`/`S0.YSIZE` равны размеру площадки, Corner Radius **50%**, Select Corners включён. Скруглены только углы внешнего торца: Upper Right и Lower Right. У левого пятака поворот 180°, поэтому те же правые углы оказываются снаружи. `PRIMITIVEINDEX` — номер примитива с нуля.

Эталон SME:

| Размеры | SME |
|---|---|
| band 1 | 0.025 |
| band 2 | 0.05 |
| band 3+ | 0.1016 (≈ 4 mil) |

## 6. Mechanical 1 — контур корпуса (TopPackage)

Слой Altium: **Mechanical 1** (layer id **57**).  
Назначение: показать **тело** компонента и зону терминалов, не шелкографию платы.

Типовой набор для chip 2-pad (6 линий толщиной `M1_w`):

1. Прямоугольник корпуса: **внешний край** линии = контур тела  
   ```
   hx = body_L/2 − M1_w/2
   hy = body_W/2 − M1_w/2
   ```
2. Две вертикальные линии терминалов внутри прямоугольника  
   ```
   xc = hx − (I1 + I2) / 2
   ```
   (если в datasheet одна длина терминала — используй её дважды).

Если у серии нет терминальных рисок — достаточно прямоугольника тела.  
**Не** дублировать TO на M1.

Mechanical 7 (Top3DPackage) — тот же корпус, но вершинами полигона, без толщины линии:

```
(± body_L/2, ± body_W/2)
```

`body_L` и `body_W` — номинал из даташита, число до допуска ±. Высота в этот прямоугольник не входит: она только в STEP и в `OVERALLHEIGHT`. У одной EIA-длины и ширины контур M7 общий для L, N, M и для всех кодов высоты. Centerline M1 меньше этого прямоугольника на `M1_w/2` с каждой стороны; подменять одно другим нельзя. Запись контура — в теле 3D, §15.3.

## 7. Top Overlay (silk платы)

Слой: **Top Overlay** (layer id **33**).  
Толщина: `TO_w`.

### 7.1 N и M — две линии и дуги по X

Внутренний край прямых сторон и концы дуг:

```
ox = mask_outer_x + Clear + TO_w/2
oy = mask_outer_y + Clear + TO_w/2
```

Горизонтали: `y = ±oy`, вертикальных сторон нет. Слева и справа дуги, выгиб наружу по X. Радиус и углы дуги не менять. Дугу сдвигают к центру так, чтобы внешний край её штриха (`вынос + TO_w/2`) лежал на внутреннем крае линии M9, то есть внутри рамки Top Border. Концы горизонталей переносятся вместе с концами дуги.

### 7.2 L — две дуги, не рамка

Две дуги вместо засечек, выгиб наружу от корпуса. Углы верхней дуги **70° → 110°**, нижней **250° → 290°**. Центр на оси Y.

Уже нарисованный Top Overlay у L не перегенерировать и не подгонять: центры и радиусы выставлены вручную по типоразмерам. В слой L ничего не исправлять, пока об этом не попросят.

## 8. Top Border / Mechanical 9

Слой: **Top Border** (Mechanical 9, layer id **65**).  
В бинарнике Altium V7 layer id должен быть `0x01020009`, иначе линии отобразятся как Top Overlay.  
Толщина: `M9_w = M1_w`.

### 8.1 Рамка

| Плотность | Centerline рамки |
|---|---|
| **N / M** | как у Top Overlay (`ox`, `oy` из §7.1) |
| **L** | внутренний край рамки на внешнем крае mask (**без** Clear): |

```
ox_L = mask_outer_x + M9_w/2
oy_L = mask_outer_y + M9_w/2
```

### 8.2 Крест в центре (только обычный footprint, не `_NM`)

```
полный размер креста = body_W / 2
плечи               = ± body_W / 4   по X и по Y
центр               = (0, 0)
```

## 9. Сводка формул

```
M1_w      = f(band)
TO_w      = 2 × M1_w
M9_w      = M1_w
Clear     = table(band, density)      # L использует Clear_N

mask_outer = pad_outer + SME

TO_center  = mask_outer + Clear + TO_w/2     # N/M рамка
M9_center  = TO_center                       # N/M
           = mask_outer + M9_w/2             # L рамка

M1_body    = body outline, inset M1_w/2 so outer edge = body
M7_vertex  = (± body_L/2, ± body_W/2)        # номинал даташита, без inset
```

Порядок примитивов в footprint (рекомендуемый):  
**Pads → Designator/Comment → Top Overlay → Top Border → Mechanical 1 → 3D Body**.

## 10. `.Designator` и `.Comment`

Одинаковые для обеих строк:

| Параметр | Значение |
|---|---|
| Шрифт | TrueType **GOST type A** (как в шаблоне библиотеки) |
| Height / Stroke | одинаковые у Designator и Comment |
| Position | `(0, 0)` mm |
| Justification | Middle Centre |
| Бинарные Location | i32 @**244** / @**248** (не legacy @13/@17) |

Высота подгоняется так, чтобы образец из **4 символов** (для резисторов — `R103`) по ширине ≈ `SPAN`:

```
Height = round_to_0.05( SPAN / (4 × 0.50) )
Stroke = clamp(Height / 6, 0.025 … 0.20)
```

Коэффициент `0.50` — оценка ширины глифа GOST type A относительно Height.  
Для другого префикса designator (C, L, …) оставь тот же расчёт по 4 символам, либо замени образец, сохранив `ширина_образца ≈ SPAN`.

## 13. Чеклист перед сдачей footprint

1. Offset пятаков = 0; два пятака симметричны относительно (0,0).  
2. `TO_w = 2×M1_w`, `M9_w = M1_w`.  
3. N/M: торцы TO — дуги наружу по X; внешний край дуги внутри рамки M9. Радиус и углы дуги не менять, только сдвиг.  
4. L: TO = две дуги, углы 70°→110° и 250°→290°. Готовый слой не перезаписывать. M9-рамка без Clear.
5. Крест M9 = `body_W/2`, есть только без `_NM`.  
6. M1: внешний край штриха = контур тела. M7: вершины ровно ±`body_L/2`, ±`body_W/2` из даташита.  
7. Тексты в (0,0), Height кратен 0.05, ширина образца ≈ SPAN.  
8. `_NM`: нет M1, нет 3D, нет креста, нет TopMask; рамка M9 и TO (линии или дуги по плотности) на месте. Внешние углы пятаков скруглены и у `_NM`.  
9. Координаты линий кратны 0.01 mm.
10. STEP вложен в `Library/Models/<n>`, имя модели — только имя файла (§15).
11. `FILENAME` внутри библиотеки оканчивается на `.$$$`, идентификатор `FileHeader` принадлежит этой библиотеке (§16).

---

## 14. Как перенести на другую серию

1. Возьми land pattern и body из datasheet → §1.  
2. Определи band по размеру → §2.  
3. Построй N, затем L/M от N → §3–5.  
4. Прогони M1 / TO / M9 / тексты теми же формулами → §6–10.  
5. Склонируй `_NM` и примени §11.  
6. Вложи STEP по §15 и сохрани идентификатор файла по §16.  
7. Числа Yageo RC из приложения A в другую серию не переносить — переносить отношения (2×, Clear, края).

## 15. 3D-модель внутри PcbLib

STEP хранится в OLE-файле библиотеки. Внешний путь в записи модели Altium не подхватывает: он ищет файл снаружи и не берёт поток из архива.

Эталон — `Discrete_Resistors_Ceramic_SMD.PcbLib`, footprint `RESC0805N`:

| Где | Что лежит |
|---|---|
| `Library/Models/Header` | u32 LE, число моделей (у резисторов 13) |
| `Library/Models/Data` | каталог, одна запись на модель |
| `Library/Models/7` | zlib (заголовок `78 9C`) от `Discrete_Resistors_Ceramic_SMD_0805.stp` |
| тело footprint, запись rid 12 | `MODELID` / `MODEL.NAME` / `MODEL.CHECKSUM` той же модели |

Распакованный поток начинается с `ISO-10303-21` и побайтно совпадает с STEP в каталоге корпусов. Сжатие — обычный zlib, уровень по умолчанию.

### 15.1 Имя — только файл

В каталоге и в теле одно и то же имя, без диска и без каталогов:

```
NAME=Discrete_Resistors_Ceramic_SMD_0805.stp
MODEL.NAME=Discrete_Resistors_Ceramic_SMD_0805.stp
```

Полный путь (`C:\Electronics\...\file.stp`) в эти поля не писать. Файл на диске остаётся исходником; в библиотеку попадает его копия.

### 15.2 Запись каталога

`Library/Models/Data` — последовательность блоков `[длина u32 LE][текст]`. Длина включает завершающий `\0`. Текст без ведущей черты:

```
EMBED=TRUE|MODELSOURCE=Undefined|ID={GUID}|ROTX=0.000|ROTY=0.000|ROTZ=0.000|DZ=0|CHECKSUM={signed}|NAME={filename}\0
```

Номер записи (0, 1, 2, …) — это имя потока `Library/Models/<n>`. `ID` — GUID в фигурных скобках, верхний регистр. Один STEP — один поток; все footprint этой высоты ссылаются на этот `ID`.

### 15.3 Поля тела

У монтируемого footprint в записи Component Body (rid 12):

| Поле | Значение |
|---|---|
| `MODELID` | тот же GUID, что `ID` в каталоге |
| `MODEL.EMBED` | `TRUE` |
| `MODEL.NAME` | то же имя файла |
| `MODEL.CHECKSUM` | та же сумма, что `CHECKSUM` каталога, десятичным **беззнаковым** u32 |
| `MODEL.MODELTYPE` | `1` |
| `MODEL.MODELSOURCE` | `Undefined` |
| `MODEL.3D.ROTX/Y/Z` | `0.000`, если корпус не повёрнут |
| `MODEL.3D.DZ` | `0mil`, если модель уже в нуле |
| `OVERALLHEIGHT` | высота корпуса в mil |

`CHECKSUM` в каталоге — те же 32 бита, записанные как **знаковый** i32: если значение ≥ 2³¹, вычесть 2³². Пример резистора 0805: в теле `2636514743`, в каталоге `-1658452553`.

Контур Mechanical 7 лежит в этом же теле: после текста параметров u32 числа вершин и пары double (внутренние единицы, 1 мм = 10000/0.0254). Порядок, как у принятого `CAPC1210N_25`: `(-L/2, -W/2)`, `(L/2, -W/2)`, `(L/2, W/2)`, `(-L/2, W/2)`. `L` и `W` — номинал даташита до знака ±. У Samsung CL 1210 это 3.20 × 2.50 мм, то есть ±1.60 × ±1.25. Толщина M1 эти вершины не сдвигает.

Контур шаблона резистора после клонирования остаётся чужим и зависит от band: 1210 собран с `RESC0805`, поэтому до правки там был прямоугольник ±1.00 × ±0.625 мм. Его заменяют на корпус этой детали. `IDENTIFIER` — десятичные коды символов имени STEP без расширения (`Discrete_Capacitors_Ceramic_SMD_1210_25`), не имя донора.

Сборка конденсаторов, которая это выполняет: `Discrete\Capacitors\Ceramic\Footprints\build_capacitor_footprints.py`.

У `_NM` записи Component Body нет: ни `MODEL.NAME`, ни потока под этот footprint.

### 15.4 Контрольная сумма

Считать по **несжатым** байтам STEP. Это не CRC32 и не Adler32.

```
checksum = (sum(i * byte[i] for i in 0 .. n-1) + 73) mod 2^32
```

`i` — индекс байта с нуля. Добавка `73` проверена на всех 13 моделях `Discrete_Resistors_Ceramic_SMD.PcbLib`: у каждой `sum(i * byte[i])` ровно на 73 меньше записанной суммы. Тело и каталог получают одну и ту же сумму; расхождение между ними Altium не принимает. `zlib.crc32` в эти поля не писать.

### 15.5 Проверка после сборки

1. Поток `Library/Models/<n>` распаковывается в `ISO-10303-21` и совпадает с файлом STEP.
2. В `NAME` и `MODEL.NAME` нет `\` и `/`.
3. `MODELID` тела равен `ID` каталога, имена равны, биты контрольной суммы равны.
4. Сумма считается формулой §15.4.
5. У `_NM` строки `MODEL.NAME` нет.
6. Вершины M7 равны ±`body_L/2`, ±`body_W/2` номинала даташита и совпадают у L, N и M одной высоты.

## 16. Файл библиотеки, который Altium согласен открыть

Библиотека — OLE compound версии 3, сектор 512 байт. Версия 4 (сектор 4096) Altium не принимает.

### 16.1 `FILENAME` — рабочее имя `.$$$`

В параметрах `Library/Data` Altium хранит имя открытого документа, даже после сохранения в `.PcbLib`:

```
FILENAME=C:\Electronics\Discrete\Resistors\Ceramic\Footprints\Discrete_Resistors_Ceramic_SMD.$$$
```

Так же записана исходная библиотека конденсаторов. Путь к `.PcbLib` в этом поле помечает документ изменённым при каждом открытии, и рядом остаётся временный файл.

### 16.2 Идентификатор `FileHeader`

Поток `FileHeader` — 53 байта, текст `PCB 6.0 Binary Library File`, в хвосте 8 символов идентификатора файла.

| Библиотека | Хвост `FileHeader` |
|---|---|
| резисторы | `UIIZAEES` |
| конденсаторы (исходный файл и `.PcbLib.bak`) | `NYUAVPUA` |

Новая или пересобранная библиотека сохраняет **свой** идентификатор. Копировать хвост из библиотеки-донора нельзя: при двух открытых файлах с одним идентификатором Altium считает их одним документом и не даёт сохранить правки. Для конденсаторов источник идентификатора — `Discrete_Capacitors_Ceramic_SMD.PcbLib.bak`, не библиотека резисторов. `FileVersionInfo` у этих двух библиотек совпадает, его можно взять из донора.

### 16.3 Когда файл можно перезаписать

Подменять `.PcbLib` нельзя, пока этот документ открыт в Altium. Признак открытого документа: заголовок окна содержит имя библиотеки, рядом лежит `Имя.$$$`, либо файл не открывается на запись. Сам процесс `X2` при этом может оставаться запущенным — закрытый документ перезаписывается. Подмена файла у открытого документа оставляет обломок: OLE из `FileHeader` и `Library`, без посадочных мест (у конденсаторов такой файл был 123904 байта). Сохранение этого обломка затирает библиотеку.

Порядок записи: закрыть библиотеку в Altium и не сохранять обломок, убедиться, что заголовок окна больше не называет этот `.PcbLib`, файла `Имя.$$$` нет и файл открывается на запись, затем записать `.PcbLib`. Обломок без посадочных мест после закрытия документа удалить. Пока документ открыт, его `.$$$` не удалять — это рабочая копия Altium.

`*.$$$` не коммитить. Каталог `History\` — локальная история Altium, в git не входит.

### 16.4 Пятаки `_NM` при правке бинарника

Флаги «маска снята» у DNP живут в записи пятака и уже выставлены в `_NM` библиотеки резисторов. Клонировать надо этот шаблон. Запись SME стоит в смещениях 90 и 121 блока размеров; соседние байты маски не переписывать, иначе у `_NM` снова включится TopMask.

## 17. STEP из параметрической детали Inventor

Один скрипт, одна деталь и одна таблица лежат в одной папке и называются одинаково:

```
Name.py
Name.ipt
Name.xlsx
```

Скрипт смотрит на своё имя и открывает соседние `Name.ipt` и `Name.xlsx`. Абсолютных путей в нём нет. Запуск: `py -3 Name.py`.

Рабочие экземпляры:

| Серия | Папка |
|---|---|
| Конденсаторы | `Discrete\Capacitors\Test\` (`Capacitors_SMD.*`) |
| Резисторы | `Discrete\Resistors\Ceramic\Packages\` (`Discrete_Resistors_Ceramic_SMD.*`) |

### 17.1 Таблица

Лист `Models` — строка на типоразмер.

| Столбец | Куда идёт |
|---|---|
| `File` | имя STEP, которое скрипт запишет рядом с собой |
| `Model` | метка строки; в деталь не пишется |
| остальные | параметры Inventor, выражение как в модели: `1 mm`, `vl1 / 5 ul` |

Лист `Parameters` — имя и тип. `String` (`vTextSize`) скрипт пишет в кавычках. Остальное передаёт как выражение.

Соответствие символам §1: `vL` = `body_L`, `vW` = `body_W`, `vH` = `body_H`, `vl1` = `I1`, `vl2` = `I2`. В таблицу кладётся номинал даташита, число до знака ±. `vS`, `vl1s`, `vr1`, `vr2` — припуски и скругления модели, не медь footprint. `vTextSize` — текст на корпусе, обычно код EIA.

Если у одного EIA несколько высот, код высоты входит в `File` (`Capacitors_SMD_0603_05.step` и `Capacitors_SMD_0603_11.step`). У резисторов высота одна, суффикса нет.

Новый типоразмер уже существующей серии — новая строка. Скрипт не меняют.

Новая серия — копия этого скрипта под именем её `.ipt` (§0, шаг 3). Меняются только имя файла и набор столбцов: в таблицу попадают параметры, которые человек завёл в модели. Формулу надписи оставляют, если корпус двухвыводный и текст стоит между поясками `vl1` и `vl2`. Для другого расположения выводов ширину текста задают по размеру из Mount-PDF, а не по `vL − vl1 − vl2`.

### 17.2 Что делает скрипт

1. Все `Name*.step` в этой папке отправляет в корзину. Файлы `.ipt`, `.xlsx` и старые `.stp` не трогает.
2. Открывает временную копию `.ipt`. Исходную деталь не сохраняет.
3. Подставляет параметры строки и пересчитывает через `Update2(True)`. Строгий пересчёт обрывается на первой ошибке и оставляет корпус предыдущего типоразмера.
4. Надпись `vTextSize` вписывает между контактами. Ширина текста не больше `vL − vl1 − vl2`. Это `L − 2·BW`, когда оба пояска равны; если `vl1` и `vl2` разные, вычитаются оба. Inventor округляет высоту шрифта, поэтому берётся наибольший размер, который ещё помещается. Найденное значение записывается обратно в столбец `vFont`.
5. Пишет STEP AP214 под именем из `File`. В `PcbLib` этот файл вкладывается по §15; в поля имени библиотеки попадает имя файла, не путь.

Перед сдачей серии проверь, что габарит тела Contacts совпал с `vL × vW × vH`, а ширина надписи не больше промежутка между контактами.
